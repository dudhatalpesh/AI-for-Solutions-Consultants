# Responsible AI Checklist

> **Status: outline.** Structure is ready to use; worked examples are tracked in [docs/11-suggested-first-issues.md](../docs/11-suggested-first-issues.md) (issue #14).

Not legal advice. Involve the customer's legal, privacy and compliance teams.

| Principle | Questions | Evidence | Status |
|---|---|---|---|
| Purpose and proportionality | Is AI the right tool? Is the use case documented and approved? | Use-case record | |
| Transparency | Do users know they are interacting with AI? Are limitations disclosed? | UI text, user guide | |
| Human oversight | Where can humans review, override or stop the system? | Approval points, escalation | |
| Fairness | Could outputs disadvantage groups? How is this tested? | Test results | |
| Privacy | Is personal data minimised? DPIA done if required? Retention defined? | DPIA, retention policy | |
| Safety and security | Threat model, guardrails, red team done? | Security review | |
| Accountability | Named owner; risk acceptance; incident process | RACI, register | |
| Regulatory mapping | Applicable frameworks identified (for example EU AI Act risk tier, sector rules — check current guidance) | Mapping table | |
| Monitoring | Quality, safety and drift monitored; review cadence set | Dashboards, reviews | |
